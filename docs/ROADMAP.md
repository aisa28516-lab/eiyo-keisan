## 守ること（ユーザーの方針）

- 数値は必ず出典のあるものだけを使う。出典を画面と回答に明記する。推測で数値を作らない
- デザインは Apple の Human Interface Guidelines に従う。HIG に数値がない箇所は「仮」と明記する
- 記録に氏名を入れない前提（外部サーバーに保存されるため）
- 使えなかった資料：国立健康・栄養研究所「重量目安表（2009版）」は転用・転載を断る記載があるため不使用

## これから作るもの（2026-10-03 に依頼されたもの）

### A. モードの切り替え（自分用／栄養士用）
- Airbnb の「旅行者／ホスト」のように、画面全体が大きく切り替わる。切り替え時に読み込み画面をはさむ
- 自分用：自分の食事記録、目標との比較、次に食べるものの提案、冷蔵庫管理、レシピ
- 栄養士用：対象者（番号で管理）ごとの聞き取り記録、結果、目標設定、コピー
- データは同じアカウントの中で分けて持つ（`S.self` と `S.clients` のように）

### B. 行のスワイプ削除
- 行を横にスワイプすると赤地に白のゴミ箱が出て、タップで削除
- 実装・公開済み（左右どちらのスワイプでも出る）。向きを片方に絞るかは確認中（iOS 標準は左スワイプで右端に削除）

### C. チェーン店のメニュー
- 各社が公開している栄養成分表から、店 → メニューを選んで食事に追加できるようにする
- 未決定：どのチェーンから入れるか／データの置き場所（公開リポジトリに入れるか、本人のアカウント内だけに入れるか）
- 数値は各社の公式ページ・PDFから取り、取得日と出典を付ける

### D. 目標に応じた食事の提案
- 目標との差（不足・過剰）から、次に食べるとよい食品を成分表から計算で出す
- 未決定：ビタミン・ミネラルの目標（食事摂取基準の推奨量・目安量を性別・年齢別に入れるか）
- アプリ内に AI は入れない（無料の範囲では入れられない）。AI に相談したいときは、状況を文章にしてコピーできるようにする

### E. 冷蔵庫管理
- 食材の一覧（量、買った日、使い切りたい日）。早く使うべきものが上に来る
- 写真：アプリ内で撮った写真を小さくして行に付ける（見た目で管理しやすくする）
- 写真からの読み取り：アプリ単体ではできない。写真を Claude の会話に送り、Claude が「取り込み用の文字列」を返し、アプリに貼り付けて追加する方式を提案中
- 冷蔵庫の中身で作れるレシピ：保存したレシピと在庫を照合。新しいレシピの提案は Claude の会話で行う
- 不足している栄養を、冷蔵庫の中身から補う候補を出す
- 食事を記録したら在庫から引く（自分用モード）
